# 交接说明 · 幻想乡电力投资集团官网

> 给接手社团网站维护的人看。看完这一份，你应该能独立更新网站，不需要问原作者。
>
> 最后更新：2026-09-18（对应官网 v0.13 / 后台 v0.13）

## 0. 一句话说清这套东西

**本地编辑 → 点「发布」写进文件 → 点个脚本打包 → 把包传上去。**

网站是纯静态的：线上只有 HTML、图片和一个 JSON 文件，**没有后端、没有数据库、没有服务器程序**。
所有"编辑能力"都跑在你自己的电脑上。

所以有两个地址，别搞混：

| | 在哪 | 谁能打开 |
|---|---|---|
| **本地** `http://127.0.0.1:8788/admin.html` | 你自己的电脑 | 只有你（服务器只监听本机） |
| **线上**（你的域名） | 托管平台 | 所有人，但它**只能看，不能改** |

改内容永远在本地改，改完再打包上传。

站点本体是**两个页面**：

| 页面 | 干什么 |
|---|---|
| `index.html` | 首页：品牌横幅、最新动态、关于社团、品牌集群、周边产品、作品展示、参展、通贩入口 |
| `notice.html` | 公告页：不带参数是公告列表，带 `?id=xxx` 是那一条公告的详情 |

两个页面都从同一个 `data/content.json` 读内容，所以后台改一次、两边同时生效。

## 1. 三分钟跑起来

**准备**：电脑上装个 Python 3（安装时记得勾 *Add Python to PATH*）。

1. 双击项目根目录的 **`启动本地预览.bat`**
   会出现一个黑色命令行窗口（**它不能关，关了服务器就停了**），浏览器会自动打开后台。
2. 登录：默认账号 `admin`，密码 `gpic2026` → **进去第一件事就是去「账号与安全」把密码改掉**。
3. 左边选页面 → 改内容 → 右上角 **`发布`** → 弹窗确认。
4. 打开 `http://127.0.0.1:8788/` 看效果。改对了就继续，改错了看下面第 4 节「出错了怎么办」。

> **想装上传压图能力（建议）**：在命令行里执行 `pip install pillow`。
> 装了之后，你上传的手机照片会被自动转成 WebP 并压到宽度 1600 以内。
> 不装也能用，只是图片按原样存进去，首屏会变慢。

## 2. 文件夹里都是什么

### 站点本体（要上传的）

| 路径 | 是什么 |
|---|---|
| `index.html` | **网站首页**。整个页面（含样式和脚本）都在这一个文件里 |
| `notice.html` | **公告页**。一个文件管两件事：直接打开 = 公告列表；带 `?id=xxx` = 某一条公告的详情 |
| `404.html` | **找不到页面时显示的页面**。访客把地址打错时看到的就是它 |
| `robots.txt` | 告诉搜索引擎哪些能抓。**这里只是一份带说明的模板**，打包时会自动生成上线版 |
| `sitemap.xml` | 站点地图。**这里不能原样上传**（里面的域名是占位符），打包时会按正式域名重新生成 |
| `assets/images/` | 所有图片。**只放处理过的成品图**，不要塞原始素材 |
| `data/content.json` | **全部文字内容的唯一来源**。网站上的每一句话都在这里 |

### 编辑工具（**绝不要上传**）

| 路径 | 是什么 | 为什么不能传 |
|---|---|---|
| `admin.html` | 管理后台界面 | 里面写死了默认密码 |
| `scripts/` | 三个 Python 小工具 | 线上没有 Python，传了也没用 |
| `启动本地预览.bat` | 双击启动本地服务器 | 同上 |
| `.workbuddy/` | 工作记录 | 无关 |

### 原始素材（不参与上线）

| 路径 | 是什么 |
|---|---|
| 根目录的 `可用背景1.png`、`幻电投 立绘logo.png`、`产品海报.jpg` 等 | 画师/美工交付的**原始文件**，只读不改 |
| `scripts/build-assets.py` | 把上面这些原始素材压成 `assets/images/` 里能用的 webp |
| `社团官网规划文档.md` | 最初的建站规划，写清了设计取舍和约束 |
| `data/.backup/` | 历史版本备份（自动生成，最多留 30 份） |

### 自动生成（别手动改）

| 路径 | 是什么 |
|---|---|
| `dist/` | `deploy.py` 打出来的发布包，**这个目录里的东西才是要上传的** |
| `发布报告.txt` | 每次打包的报告：传了什么、体积多大、有没有裂图风险 |

## 3. 日常操作

### 改站点名称（也是备案要用的名字）

站点对外叫 **幻电投企划**，而站内那个「幻想乡电力投资集团」是**架空设定** ——
这是分开的两层，不要混：

| 层 | 值 | 出现在哪 |
|---|---|---|
| **站点名 / 备案名** | 幻电投企划 | 浏览器标题、分享卡片、页头页脚品牌名、页脚版权与非官方声明 |
| **架空设定（内容）** | 幻想乡电力投资集团 | 首屏大字、关于社团、品牌集群、通告正文 |

改站点名：后台「站点设置」→ **站点名称（中文）**。改完后浏览器标题、页头页脚品牌名会一起变
（静态兜底也同步过了，加载失败时不会闪回旧名）。

> 为什么要用这么个名字：个人 ICP 备案的网站名称**不允许含「集团」「公司」这类主体字眼**，
> 而「投资」「金融」属于需要前置审批的金融类词 ——「幻想乡电力投资集团」两个雷全踩。
> 「幻电投企划」都避开了，架空设定留在页面内容里不受任何影响。
>
> 这个名字改过两次（2026-09-20）：先定的是「幻想电力企划」，后来发现「**电力**」也属行业词，
> 仍有被主管部门挑出的概率，于是收紧成社团自称号「幻电投」+「企划」，中性得多。
> **「幻想电力企划」留作备案被驳回时的备选名** —— 换回来只要改 `site.name`
> 与各页静态兜底，比重报一个新名字省事。
> 详见 `上线待办清单.md` 第四节。

### 改一句话

后台左侧选对应页面 → 找到字段 → 改 → 右上角 `发布`。
带 `**双星号**` 的写法会变成**加粗**，换行会保留，别的格式不支持。

### 换一张图

图片字段旁边有两个按钮：

- **从素材库选择** —— 从 `assets/images/` 里已有的图里挑。往那个文件夹丢新图后，列表会自动出现（按"重新扫描"刷新）。
- **上传本地图片** —— 从你电脑里选一张。服务端会：
  - 自动转成 **WebP** 格式
  - 宽度超过 **1600px** 就等比缩小
  - 同名文件若内容完全一样，直接复用；不一样则存成 `xxx-2.webp`，**不会覆盖旧的**
  - 传完自动填好路径

传完看一眼右下角的提示，它会告诉你"原始 2.4 MB → 现在 180 KB，省了 92%"。

### 加一个商品 / 加一条公告

到对应页面，列表下方有 `新增一项`。每一项右边有四个小按钮：上移、下移、复制、删除。
左下角的导航数字会自动跟着变。

### 写一条图文公告（公告页）

公告页是 `notice.html`，**一个文件管两件事**：

- 直接打开 `notice.html` → 公告列表，最新的在最上面
- 打开 `notice.html?id=xxx` → 那一条公告的详情，`xxx` 就是这条公告的 `id`

首页的「最新动态」每条都指向对应的详情页，所以**首页点哪条、就进哪条**。

在后台左侧点 **公告**，展开任意一条公告，从上到下依次是：

| 字段 | 作用 |
|---|---|
| 日期 / 类型标签 / 标签配色 | 首页列表和详情页都会显示 |
| **列表摘要** | 首页那一行显示的文字。摘要和标题**都留空**时，这条连首页和公告列表都不会出现（但它还留着，方便你继续写） |
| **详情页标题** | 公告页顶部的大标题。留空就退回用列表摘要 |
| **头图** | 详情页顶部的大图。留空就是纯文字版式，一样能看 |
| **版式** | 标准（正文 720px 居中）/ 宽幅（正文 940px、头图满宽）/ 海报式（头图满铺、标题压在图上，**只有配了头图才生效**） |
| **公告 id** | 详情页地址里的那个 `xxx`。新增公告时会自动生成，一般不用动 —— 改了以后旧链接会失效 |
| **正文内容块** | 正文本体，见下 |

**正文是「内容块」拼出来的**，想怎么排就怎么排。内容块下方有一排按钮，点一下就在末尾加一个块：

| 块 | 说明 |
|---|---|
| 段落 | 普通正文。回车换行，`**两个星号**` 包住会加粗 |
| 小标题 | 带绿色竖线的二级标题 |
| 项目列表 / 有序列表 | 一条一行，点「增加一条」继续加 |
| 引用框 | 浅绿底的强调框，适合放注意事项、通贩提示 |
| **单图** | 选图（素材库或上传）＋ 图注 ＋ 宽度（**整宽 / 居中 / 左浮 / 右浮**）。左浮右浮能让文字绕着图片排 |
| 多图并排 | 2–4 张图横向并排，每张可单独写图注 |
| 分隔线 | 一条虚线，用来断开上下两段 |
| 落款 | 右对齐的落款行，如「幻想乡电力投资集团 · 文化传媒部」 |

每个块的右上角都有 **上移 / 下移 / 复制 / 删除**；左侧下拉可以直接把这个块**换成别的类型**（已经写好的文字会尽量带过去）。

写完点右上角 `发布`。首页和公告页都会立刻更新。

> 提示：改了公告正文后，如果只想看效果，可以直接在浏览器里刷新 `notice.html`——
> 不用先发布，后台的草稿会在这两个页面上同时生效。

### 设置参展倒计时（首页「参展预告」）

首页「参展预告」里那格倒计时是**自动算的**，数据来自后台左侧 **参展活动** 页的
**开展时间**。填法很宽松：

| 你想表达 | 就这么填 |
|---|---|
| 10 月 6 日上午 9:30 开展 | `2026-10-06T09:30` |
| 只知道是哪一天 | `2026-10-06`（按当天 00:00 算） |

**「结束时间」可以不填。** 填了之后：展期内显示「进行中」，闭幕后显示「已结束」。
不填的话：开展当天显示「今天开展」，从第二天起显示「已结束」。

倒计时的文字和颜色会随时间自己变，不用手动改：

| 距开展 | 显示 | 颜色 |
|---|---|---|
| 7 天以上 | `18 天` | 正常 |
| 一周之内 | `5 天` | 橙 |
| 24 小时之内 | `5 小时 23 分` | 红 |
| 最后 1 小时 | `23:41`（会跳秒） | 红 |
| 开展后未结束 | `进行中` | 绿 |
| 已结束 | `已结束` | 灰 |

天数是按**日历日**算的：9 月 18 日看 10 月 6 日，就是「还有 18 天」，
不会因为当天已经过了半天就变成 17。页面每分钟都在算，标签页切到后台会暂停，
切回来立刻续上。

> **「倒计时（备用手填）」那一行，只在「开展时间」留空时才会显示。**
> 所以老数据不会被弄空 —— 不填时间，就还是显示你手写的那行字。
>
> 时间格式写错（比如写成 `2026/10/06`）时，首页会**安静地退回**去显示手填文字，
> 不会算出一个荒唐的数字；后台概览页的检查清单会告诉你「开展时间看不懂」。

### 发布

右上角 `发布` → 确认。三步之内完成：

1. 服务端把**当前**的 `data/content.json` 挪进 `data/.backup/`（留个后悔的机会）
2. 把你现在编辑的内容写进 `data/content.json`
3. 网站首页刷新即生效

### 看到顶部红色提示「浏览器里的草稿，比服务器上的内容还旧」怎么办

**先点提示条里的 `载入服务器版本`，再去改内容。**

原因是这样：后台把没发布的改动存在**浏览器**里（草稿）。如果这份草稿是在某个较早的
版本上改出来的，而 `data/content.json` 后来又被别的途径更新过（换人接手、直接改文件、
拉取别人的成果……），那这份草稿就是"基于旧版本"的。

这时候按「发布」，等于**用旧内容整片覆盖新内容** —— 后来加进去的素材和文案会一起消失，
而且以前只会弹一个一闪而过的提示，很容易没看见。现在系统会主动拦住：

- 顶部常驻红色提示条，并列出两个版本的时间
- 点「发布」时先弹窗三选一：`载入服务器版本` / `强行用草稿覆盖` / `取消`
- 就算你绕过了前端，服务端也会用**内容指纹**校验一次，对不上就返回 409 拒绝写入
- 确实想用草稿覆盖，才走「强行覆盖」；服务端会先自动备份当前版本，仍可回滚

### 改错了想退回去

后台 →「数据与发布」→ **历史版本**：

- 每一行是一份备份，带时间和体积
- 点 `回滚到此版本` 就能退回去
- **回滚前系统会把"当前版本"也存一份**，所以回滚本身也能再撤销，不会滚丢
- 最多保留最近 30 份

### 已经上线之后，怎么更新线上内容

1. 本地改好 → `发布`
2. 跑一次 `python scripts/deploy.py`（会重新打包 `dist/`）
3. 把 `dist/` 里的内容重新传到托管平台

大部分时候其实只需要重传 `data/content.json` 和新增的图片，但整包重传最省心、也不容易出错。

## 4. 出错了怎么办

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 点发布，说「未检测到本地服务器」 | `启动本地预览.bat` 没跑，或者黑窗口被关了 | 双击 bat，然后通过 `http://127.0.0.1:8788/admin.html` 打开后台 |
| **双击** `index.html` 打开，内容和网站对不上 | 浏览器安全限制：`file://` 下读不到 `data/content.json` | 这不是 bug。看网站一定要走 `127.0.0.1:8788` |
| 发布成功了，首页却没变 | ① 没刷新 ② 浏览器缓存 | `Ctrl + F5` 强制刷新 |
| 发布报「拒绝跨站请求」 | 你用 `localhost` / 别的 IP / 装了代理插件访问的 | 统一用 `http://127.0.0.1:8788/` |
| 发布报「缺少 site 段」 | 提交的内容结构不对（一般是编辑器里的内容被清过） | 用「重新载入 data/content.json」恢复，或从历史版本回滚 |
| 顶部出现红色提示「草稿比服务器上的内容还旧」 | 你浏览器里的草稿是在旧版本上改的，磁盘上的文件已经被更新过 | 点提示条里的 `载入服务器版本`，再继续改。别点「强行覆盖」，除非你确认草稿内容才是要的 |
| 发布报「磁盘上的 content.json 已经比这份草稿新，已拒绝写入」 | 同上一行，服务端把"用旧盖新"拦下来了 | 同上。确实要用草稿覆盖：在弹窗里选「强行用草稿覆盖」 |
| 前台少了刚接进去的图 / 文案 | 多半是被一份旧草稿覆盖过 | 「数据与发布」→ 历史版本 → 找到覆盖前的版本 → 回滚 |
| 上传报「不支持的图片格式」 | 只接受 webp / png / jpg / jpeg / gif / svg / avif | 先转成这些格式之一 |
| 上传报「图片解码失败」 | 文件后缀是 png 但内容其实不是图片，或文件损坏 | 换一张重新导出 |
| 改了后台，前台没反应 | 你改的字段前台可能没用到（例如"简称"当前无处显示） | 确认一下这个字段在前台有没有对应位置 |
| 启动时说「无法监听 8788」 | 已经有一个服务器在跑，或端口被别的程序占用 | 关掉旧的命令行窗口；找不到就重启电脑 |
| 传图后首页变慢 | 上传的图太大（没装 Pillow，没压缩） | `pip install pillow`，或先用画图工具把图压到 300 KB 以内再传 |
| 内容全乱了 | 改错了 | 「数据与发布」→ 历史版本 → 回滚 |
| 线上输错地址，看到的是托管商的英文错误页 | `404.html` 没传上去，或托管平台没开自定义 404 | 确认发布包里有 `404.html`，并在托管平台设置里指定它为 404 页面 |
| 线上 `robots.txt` / `sitemap.xml` 打不开 | 这两个文件没传，或 sitemap 因没给域名而没生成 | 见第 5 节。`sitemap.xml` 必须带 `--site-url` 打包才会生成 |
| sitemap 里的地址是 `__SITE_URL__` 开头 | 手工上传了根目录那份模板，没跑打包脚本 | 重新跑 `python scripts/deploy.py --site-url 你的域名`，用 `dist/` 里的版本 |
| 微信里转发没有预览图 | `siteUrl` 没填，`og:image` 只能是相对路径，抓不到 | 后台「站点设置」填正式域名，或打包时加 `--site-url` |
| 参展倒计时一直显示「已结束」 | 「开展时间」填的是过去的日期 | 后台「参展活动」改「开展时间」。展会已办完就该更新成下一场，或直接清空它（清空后显示手填那行字） |
| 参展倒计时显示的是手写文字，不是自动算的 | 「开展时间」留空或格式看不懂 | 格式要像 `2026-10-06T09:30`；只写 `2026-10-06` 也行。写成 `2026/10/06` 不认 |
| 打包时报 `trash` / 回收站相关的错 | 本机装了「删除先进回收站」的安全策略，`deploy.py` 旧版用的 `shutil.rmtree` 被它接管 | 已修（v0.13 起改为逐个删）。若仍在别处遇到：手动删掉 `dist/` 再跑一次 |
| 密码忘了 | 只能本机重置 | F12 → Application → Local Storage → 删掉键 `gpic.admin.auth.v1`，刷新即恢复默认账号 |

## 5. 上线（部署）

> 📋 **动手之前先看根目录的 `上线待办清单.md`** —— 它按「已完成 / 缺素材 / 缺基建 / 待决策」四类列出了上线前还差什么，可直接勾选。

```bash
# 在项目根目录执行。把域名换成实际的，用来让微信/QQ 转发时有预览图
python scripts/deploy.py --site-url https://你的域名
```

脚本会把发布包生成到 `dist/`，并且：

- ✅ 只复制 `index.html`、`notice.html`、`404.html`、`robots.txt`、`sitemap.xml`、`assets/`、`data/content.json`
- ✅ 自动把发布副本的 **`showAdminEntry` 关掉**（线上没有 `admin.html`，不关的话访客点进去是 404）
- ✅ 自动把 `siteUrl` 写成你给的域名（分享卡片的 `og:image`、`og:url`、`canonical` 会用它）
- ✅ **按 `content.json` 的真实内容重新生成 `sitemap.xml`**（含首页、公告列表、以及每一条已发布的公告详情页）
- ✅ 把 `robots.txt` 的注释剥掉、按域名写上正确的 `Sitemap` 行
- ✅ 剔除 `admin.html` 和 `scripts/`
- ✅ 体检：内容里引用的图片**有没有缺失**（会裂图）、单张图有没有超过 300 KB
- ✅ 算出**首屏体积**，对照 500 KB 的预算
- ✅ 把报告写到项目根的 `发布报告.txt`

> ⚠️ **不给 `--site-url` 会怎样**：发布包里**不会出现 `sitemap.xml`**，`robots.txt` 里也不会有 `Sitemap` 行。
> 这是故意的 —— 站点地图必须写绝对地址，放一份填着占位域名的上去，只会让搜索引擎反复抓失败。
> 域名定下来之后加 `--site-url` 重新打包，两个文件就都对了。
> （根目录那份 `sitemap.xml` 是**给手工上传用的备用模板**，里面有 `__SITE_URL__` 占位符，
> 不跑打包脚本就得自己替换成真实域名。正常流程不用管它。）

## 6. 账号与安全（必须知道）

### 后台登录是"纸糊的"

密码只存在**你这台电脑的浏览器**里（加盐哈希），服务端不做校验。
它解决的问题是"**别让人误点到编辑入口**"，**不是**"防止别人入侵"。
懂技术的人绕过它并不难。

所以：**`admin.html` 绝对不能上传到公网。** 这是整套流程里唯一一条不能破的红线。

如果哪天真要把后台放到公网上，请不要再依赖这层登录，改用 Cloudflare Access 之类的正经方案。

### 本地服务器做了什么防护

- 只监听 `127.0.0.1`，局域网和外网都连不上
- 校验 `Host` / `Origin` 必须是本机地址 —— 挡住"你浏览器里某个网页偷偷把内容覆盖掉"这类攻击
- 写入前检查内容结构完整，避免把站点刷成空壳
- 每次发布自动备份，最多保留 30 份

### 备份在哪

`data/.backup/` 里，文件名形如 `content-20260918-092235-417.json`。
这是**最后一道保险**，不要手动删除这个目录。

## 7. 改内容结构时的注意事项（给后来接手技术的人）

`index.html`、`notice.html` 和 `admin.html` 里各有一个常量：

```js
var MIN_VER = 5;   // 内容结构版本
```

（v4 起公告条目带上了 `id` / `title` / `cover` / `layout` / `body` 正文内容块；
v5 起参展板块带上了 `date` / `dateEnd`，首页倒计时由它们自动算。
**注意 `notice.html` 里也有一份 `MIN_VER`，三处必须一起改。**）

**背景**：后台的编辑内容会先存在浏览器里（localStorage），刷新不丢。
但如果你给 `content.json` 加了新字段、升了版本号，浏览器里那份旧草稿会反过来把新内容盖掉。

所以规则是：

> **每次新增 / 重命名字段，必须同时改这几处**：
> `data/content.json` 的 `version`、`admin.html` 里的 `DEFAULT_CONTENT.version`、
> 以及 `index.html` / `notice.html` / `admin.html` 三边的 `MIN_VER`。
> 版本低于 `MIN_VER` 的草稿会被自动作废（这就是它的作用）。

另外，后台表单是**由数据驱动的**：`admin.html` 里的 `PAGES` 数组（含各页 `fields` 定义）决定有哪些编辑框。
加字段 = 在 `PAGES` 里加一项 + 在 `index.html` 的渲染代码里读这个路径。两处都要改。

公告正文用的是一种单独维护的字段类型 —— `type: 'blocks'`：

- 后台的编辑器在 `admin.html` 的 `renderBlocks()` 与 `BLOCK_KINDS`
- 前台的渲染器在 `notice.html` 的 `renderBlock()`
- **两边的 `kind` 必须对得上**（`p` / `h` / `ul` / `ol` / `quote` / `img` / `imgs` / `hr` / `sign`）。
  加一种新块 = 两边各加一处；前台遇到不认识的 `kind` 会直接跳过，不会把页面渲染崩。

### 还有一层：内容指纹（`gpic.admin.draftbase.v1`）

`MIN_VER` 只能挡住"**结构变了**"的覆盖，挡不住"**只改了值**"的覆盖 —— 比如只是把
`brands.items[2].logo` 从一个路径改成另一个，`version` 还是 3。这种事真实发生过一次：
4 个成员单位 logo 接进 `content.json` 后，被浏览器里一份旧草稿整体盖没。

为此加了第二层：**内容指纹**。

- `scripts/serve.py` 给 `content.json` 算一个 16 位指纹（对字段值 `sort_keys` 后取 SHA-256，
  与 JSON 怎么写无关），`/api/ping` 会把它带出来
- 后台把"这份草稿基于哪个版本"记在 localStorage 的 `gpic.admin.draftbase.v1`（`{fp, at}`）
- 发布时后台带上请求头 `X-Content-Base`；服务端比对当前指纹，对不上就 **409 拒绝**
- `index.html` 也读那个键：草稿基线早于 `content.json` 的 `updatedAt` 时，前台**忽略草稿**

**你不需要记这些**，只要知道：看到红色提示条就点「载入服务器版本」。
但要**手工**改 `data/content.json`（绕过后台）时注意——改完刷新一下后台，
再点一次「载入服务器版本」，让草稿与文件重新对齐；否则下次发布会被拦下来。

## 8. 目前已知的限制 / 待补

**功能上的限制**

- 后台登录不是真鉴权（见上）
- 只能在本机编辑；线上内容靠"重新打包上传"更新
- 普通字段的富文本只支持 `**加粗**` 和换行；**公告正文走"内容块"，可以排版和插图**（见 3. 写一条图文公告）
- 公告页是纯前端筛选：所有公告都在同一个 `content.json` 里一次全量加载。公告到几百条时应该改成分页，目前这个量级远远够用
- 公告的地址参数 `id` 一旦改动，之前分享出去的链接就会失效（新增时自动生成，平时不用碰）
- 没有草稿预览页 / 没有多语言（导航里的"中/日"切换已隐藏，日文文案就绪后再放开）

**上线基建上的限制**

- `sitemap.xml` **只有带 `--site-url` 打包时才会生成**。不填域名时发布包里不会有它 —— 这是有意的，理由见第 5 节
- `404.html` 用「站点根绝对路径」（以 `/` 开头），**要求网站放在域名根目录（或独立子域）下**。放在子目录里托管时需要改路径，详见第 5 节的说明
- 分享卡片图 `assets/images/share.jpg` 由 `scripts/build-assets.py` 从同一张横幅生成，
  **刻意用 JPEG 而不是 WebP**：它只被微信 / QQ / 微博的抓取程序取用、不进首屏，
  而微信与 QQ 的链接预览对 WebP 支持不稳，换成 WebP 有让预览图直接不显示的风险。
  改这块之前先读 `build-assets.py` 里 `SHARE_WIDTH` 上方的注释
- 公告**有头图时**，页面会把 `og:image` 换成该头图，并**删掉** `og:image:width/height`
  这对尺寸标注（那对数字是分享图的，标在头图上会让平台按错误比例裁切）。
  想让分享效果最好，公告头图本身也按接近 1.9:1 的横图来做

**素材上的空缺**（写文案时留意）

- 5 张品牌卡片 logo 已全部到位。注意**成员单位 logo 都是"浅色标识 + 透明底"，是照深色背景设计的**（放白底上标准字会完全消失），所以品牌卡片用了深色底；想改回浅色卡片，先读 `index.html` 里「8. 品牌集群」上方的注释
- 缺画集/插画封面、周边实物图、摊位图
- 公告页目前只有 1 条公告设了头图，**其余 3 条的头图与正文配图都还是空的**（文章正文已经写好，配图随时可在后台补）
- 微博 / B 站 / X / Pixiv / 微店 / Booth 链接都还空着
- 展会名称、日期、摊位号还是占位。**倒计时已经会自动算了，但它读的是 `event.date`
  里那个占位日期（2026-10-06）** —— 展会定下来后，去后台「参展活动」改「开展时间」，
  倒计时会立刻跟着变；不改的话，10 月 6 日一过就会显示「已结束」
- 公告里的日期是编者定的，不是真实发布时间

**内容红线（写文案时守住）**

- 所有"幻想乡五大发电集团"相关的表述**必须明确标注是东方 Project 二次创作架空设定**，不能与现实中的发电集团体系混淆。站点首页导航下方有一条常驻声明条，别删
- 不做社区、不做论坛、站内不收款
- 沿用社团自有口号「由幻想，向未来」；不要用「你用电，我用心」（那是现实企业的口号）

## 9. 以后想升级成"在任意设备上改线上内容"

现在的架构是**本地编辑 → 打包上传**。以后如果想：
**打开网页就能改线上站点、多个人协作、改完自动上线** —— 那是另一套架构（Git 型 CMS，如 Decap / Sveltia）。

好消息是**这不需要推倒重来**：

- `data/content.json` 是一个中立的、结构稳定的 JSON 文件，任何 CMS 都能把它当内容源
- 迁移 = 把它导入 Git 仓库 + 换一个编辑前端，是**加一层**，不是重写

风险提示：那类方案通常依赖 GitHub OAuth，国内访问可能不稳定，实际门槛未必比"双击一个 bat"低。
