# 技术选型评估：nginx 与 Vue3

> 评估日期 2026-09-21 · 评估对象：本站（幻电投企划官网）是否迁移到 nginx 托管、是否引入 Vue3
> 结论先行：**nginx 直接上（零代码改动）；Vue3 建议先别动，最多先改后台。**

---

## 一、结论摘要

| 议题 | 建议 | 改动量 | 风险 |
|---|---|---|---|
| **用 nginx 托管** | ✅ **上，现在就上** | 新增 1 个配置文件（约 40 行），**不碰任何现有代码** | 极低 |
| **全站换 Vue3** | ❌ **不建议** | 重写 3668 行 JS + 新增构建链 + 5 套验证全重做 | 高（会打掉 SEO 与分享卡片） |
| **只把后台换 Vue3** | 🟡 可做，性价比最高 | 重写 `admin.html` 的 2682 行 JS | 中（后台不影响访客） |
| **前台轻量组件化** | 🟡 备选 | CDN 引入 petite-vue / Alpine，**无构建** | 低 |

理由一句话：**本工程现在最大的资产是「静态、零构建、任何抓取器都能读到」；而 Vue3 SPA 恰好要拆掉这三样。**

## 二、现状实测（2026-09-21 扫描）

### 体量

| `index.html` | 80.5 KB | 1498 | **520 行**（2 块） | 301 行 |

### 关键架构特征（本次扫描发现）

1. **零构建链**：无 `package.json`、无 `node_modules`、无 `vite.config.*`。改一个错别字直接改 html，`python scripts/serve.py` 就能看效果。
2. **「静态标记打底 + JS 定点贴片」**，不是「JS 渲染整页」：
   - `index.html` 里只有 **3 个** `getElementById`（`langSwitch` / `mainNav` / `navToggle`）
   - 只有 **1 处** `innerHTML` 赋值
   - **0 个模板字符串**（反引号）
   - → 说明真实文案与 `og:meta` 都是**写死在 HTML 里的**，JS 只在有值时做覆盖
3. **`index.html` 22 个函数**：`$` / `esc` / `rich` / `badge` / `setText` / `setHTML` / `meta` / `absUrl` / `setCanonical` / `ts` / `renderWorks` / `apply` + 倒计时 9 个（`cdParse`–`cdStart`）+ 草稿防护 3 个（`draftBaseAt` / `draftStale` / `pick`）
4. **产物**：`dist/` 34 个文件 / 1.93 MB，最大单文件 `banner.jpg` 227.9 KB（是 `<picture>` 里的兼容兜底，现代浏览器走 `banner.webp` 115.6 KB，**不会下载**）
5. **现有验证套件 5 套 178 项**：语法 6 块 / jsdom 渲染 71 / 分享卡片 14 / 倒计时 44 / 一致性 33

## 三、nginx 评估：这不是「改动」，是「收货方」

本站产出物是一个纯静态目录（`dist/`），nginx 天生就是干这个的。**现有代码一行都不用动。**

### 要新增的只有 1 个配置文件

- `root` 指向 `dist/`，`index index.html`
- `try_files` + `error_page 404 /404.html`
- gzip 压缩（html / css / js / json / svg）
- **分类缓存策略**（见下方红线）
- HTTPS + http→https 跳转（certbot 自动续期）

### ⚠️ 四条本站专属的红线

1. 🔴 **必须部署在域名根或独立子域，不能挂子目录** —— 因为 `404.html` 是全站唯一刻意使用**根绝对路径**的页面（前提就是网站位于根）。挂到 `/gpic/` 下会全断。
2. 🔴 **`content.json` 绝不能长缓存** —— 本站内容是**运行时 `fetch`** 的。如果给 json 设了 `max-age=31536000`，你在后台改了内容，访客浏览器还在吃一年前的旧 JSON。**json / html 一律 `no-cache` 或 ≤1 小时。**
3. 🔴 **`admin.html` 建议在 nginx 层直接封掉**：`location = /admin.html { return 404; }`。上线策略本来就是「不传 admin.html」，但**靠 nginx 拦比靠「记得别传」更硬**，能防手滑。
4. 🔴 **绝不要把 `/api/*` 暴露到公网**。现在的后台接口：**无 token 级鉴权**，同源校验只放行 `127.0.0.1:8788` / `localhost:8788`。一旦公网可达，等于「任何人都能覆盖你的 content.json」。若要保留在线后台，必须反代到 `serve.py` **且加 basic auth / IP 白名单**，否则只是本机用。

### 工作量

**半天以内，且不增加任何维护负担**（配置文件写完基本不用再碰）。反而顺手解决三件现在没有的事：gzip 压缩、静态资源长缓存、HTTPS。

## 四、Vue3 评估：真动刀，而且大概率是负收益

### 4.1 工作量：3668 行 JS 全部过一遍

不是「加个框架」，是把 `index.html` 520 行 + `notice.html` 455 行 + `admin.html` 2682 行**全部重写**，同时新增构建链。

### 4.2 三处现有机制会被打散

| 现有机制 | 换 Vue3 SPA 后 | 后果 |
|---|---|---|
| **静态兜底**（HTML 里就有真文案，JS 挂了降级显示旧文案） | 概念消失，HTML 变空壳 | 🔴 **脚本一挂就是白屏**；`file://` 双击预览也会白屏（现在至少能看） |
| **SEO / 分享卡片**（`og:image` / `og:url` / `canonical` 全靠静态 meta） | 全靠运行时注入 | 🔴 **微信 / QQ / 微博抓取器不执行 JS** → 分享卡片直接失效。**之前专门做的 `share.jpg`（1200×700、特意避开 WebP 因为微信不认）、公告头图切 og:image 那一整套全部白干** |
| **`MIN_VER` 五处同步闸门 + 内容指纹乐观锁 + 陈旧草稿防护**（v0.10 真出过覆盖事故才加的护栏） | 逻辑要重新设计 | 🟡 不能照搬，需重做并重跑验证 |

### 4.3 收益是什么？诚实说

- **组件复用**：卡片渲染、倒计时、内容块渲染（前台 `renderBlock()` / 后台 `renderBlocks()`）在 `index` 与 `notice` 之间确有重复。
- **后台表单**：`admin.html` 的 2682 行确实会显著受益于响应式。

### 4.4 代价

- **引入构建链**：从「双击 html 就能看」「`python serve.py` 就开工」变成「改一个字也要 `npm run build`」。
- **分发变重**：`node_modules` 几百 MB；现在是零依赖，拷贝即用。
- **验证套件重写**：5 套 178 项断言要全部重做（其中一致性 33 项在 SPA 下已无意义，因为「兜底」不存在了）。

### 4.5 什么情况下 Vue3 才值得

站点变成**多路由、多页面、多人协作维护**，或者后台交互复杂度再上一个量级。目前是 **3 个页面（index / notice / 404）+ 1 个后台**，不满足条件。

## 五、改动规模量化对比

| 方案 | 触碰文件 | 改动量 | 对 SEO / 分享 | 对现有验证 |
|---|---|---|---|---|
| **① nginx 静态托管** | 新增 1 个 conf | ~40 行新增 | 无影响（并获 gzip / 缓存 / HTTPS） | 完全不用动 |
| **② 后台换 Vue3（CDN 渐进）** | `admin.html` | 重写 2682 行 JS | 无影响（admin 本就 noindex、不随站发布） | 只需为后台单独加重测 |
| **③ 前台 Vue3 + Vite SPA** | `index` / `notice` / `404` + 新增构建链 | 重写 ~1000 行 JS + 构建链 + 重做 5 套 178 项 | 🔴 分享卡片失效、SEO 需另补方案 | 全部重写 |
| **④ 全站 Nuxt / SSG** | 全部 + 构建链 + 部署方式 | 全站重写（v1.0 级） | ✅ 可保住（产物仍是真 HTML） | 全部重写 |

---

## 六、建议路线

1. **立即做**：上 nginx。零风险、零代码改动，顺手拿到 gzip / 缓存 / HTTPS。
2. **想优化体验**：先只动后台（方案 ②）。`admin.html` 占全站 JS 的 **73%**（2682 / 3668），收益最大、风险最小、**前台一行不动**。用 Vue3 CDN 版（`vue.global.js`）渐进引入即可，**不需要构建链、不需要 node_modules**。
3. **前台只嫌原生 JS 累**：用 **petite-vue（~6 KB）** 或 **Alpine.js（~15 KB）** CDN 引入，渐进增强，同样不用构建。
4. **真要工程化**：一步到位上 **Vite + Vue3 + SSG（vite-ssg / Nuxt）**，保证构建产物仍是**真静态 HTML** —— 这样 SEO 与分享卡片都不掉。但这是「重写全站 + 搭构建链 + 重做验证」的 v1.0 级投入。

> **一句话**：nginx 是「换个更好的货架」，Vue3 是「把整个店拆了重建」，而你的店现在**最大的优势恰恰是它够轻**。

## 附录：nginx 参考配置模板

> ⚠️ 路径按 Ubuntu / Debian 惯例（`/var/www/...`、`/etc/nginx/sites-available/`）。CentOS / 宝塔面板需按本机实际调整。**`gpic.example.cn` 全部替换为你的真实域名。**

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name gpic.example.cn;

    # 证书签发前先用这行；certbot 会自动改写为跳转 HTTPS
    root /var/www/gpic;
    index index.html;

    # ---- 后台入口封死（上线策略：不发布 admin.html）----
    location = /admin.html {
        return 404;
    }

    # ---- 绝不对外暴露本机后台接口 ----
    location ^~ /api/ {
        return 404;
    }

    # ---- 缓存策略：内容与 HTML 绝不长缓存 ----
    # content.json 是运行时 fetch 的，长缓存会让你改了内容访客看不到
    location ~* \.(html|json)$ {
        add_header Cache-Control "no-cache, must-revalidate";
        gzip on;
    }

    # ---- 静态资源长缓存（图片几乎不会变）----
    location ~* \.(webp|png|jpe?g|gif|svg|ico)$ {
        add_header Cache-Control "public, max-age=31536000, immutable";
        access_log off;
    }

    location ~* \.(css|js)$ {
        add_header Cache-Control "public, max-age=604800";
        gzip on;
    }

    # ---- gzip ----
    gzip on;
    gzip_comp_level 6;
    gzip_min_length 1024;
    gzip_types text/plain text/css application/json application/javascript
               application/xml image/svg+xml;

    # ---- 404 走自家页面（404.html 使用根绝对路径，必须部署在域名根）----
    error_page 404 /404.html;
    location = /404.html {
        internal;
    }

    location / {
        try_files $uri $uri/ =404;
    }
}
```

启用：

```bash
ln -s /etc/nginx/sites-available/gpic /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
certbot --nginx -d gpic.example.cn      # 自动签证书并改写为 HTTPS
```

**上线前自检三条**：
1. 部署在**域名根或独立子域**，不是子目录（否则 `404.html` 全断）。
2. 访问 `/data/content.json` 响应头是 `no-cache`。
3. 访问 `/admin.html` 与 `/api/ping` 都返回 **404**。
