# 公网同步操作说明

> 一句话：**在后台点「保存」，只是存进了本机的数据库；要让公网站点变，必须双击一次
> 「同步到公网.bat」，然后等 1～3 分钟。**
>
> 线上地址：<https://gugulina.github.io/gpic-website/>
> 本地后台：<http://127.0.0.1:4321/admin.html>

---

## 一、为什么「保存了但公网没变」

系统里其实有两份数据，它们**不会自动互相跟随**：

```
   后台 admin.html                    公网 GitHub Pages
        │                                    ▲
        │ 点「保存」                          │ git push 之后自动发布
        ▼                                    │
   本机 SQLite 库  ──①导出──▶  data/content.json  ──②打包──▶  web-standalone/
   server/data/gpic.sqlite                              ──③推送──▶  仓库 → 线上
```

| 环节 | 谁来做 | 说明 |
|---|---|---|
| 后台保存 | 点按钮，立刻完成 | 只写本机 `server/data/gpic.sqlite` |
| ① 导出 | 「同步到公网.bat」 | 库 → `data/content.json` |
| ② 打包 | 「同步到公网.bat」 | 生成公网实际发布的静态快照 `web-standalone/` |
| ③ 推送 | 「同步到公网.bat」 | `git commit` + `git push`，GitHub 收到后自动重新发布 |

旧版的同步脚本**只做了 ①②，没做 ③**。所以本地文件明明已经更新，
线上却一直停在旧版本 —— 这不是缓存问题，是**内容根本没上传**。

> 注：2026-10-19 起，脚本已补上第 ③ 步，双击一次就能真正上线。

## 二、标准操作流程

### 1. 先在后台把内容改完、保存

- 打开 <http://127.0.0.1:4321/admin.html>（**不要双击 html 文件打开**，`file://` 进不了后台）
- 逐个 tab 改好，每条点「保存」
- 保存成功时状态条会多出一行提示：*「已写入本地数据库 —— 公网站点还不会变」*，这是正常的

### 2. 双击 `官网/同步到公网.bat`

位置：项目里的 `官网/` 文件夹内。

窗口会依次打印：

```
  [1/3] 导出数据库内容 -> data\content.json
  [2/3] 重建静态快照 -> web-standalone\
  [3/3] 提交并推送到 GitHub
   ...
   已推送完成。
```

### 3. 等 1～3 分钟

GitHub Actions 会自动重建并发布。进度看：

<https://github.com/gugulina/gpic-website/actions>

最新一条变成绿色 ✓（`发布官网到 GitHub Pages`）就说明上线了。

### 4. 打开线上地址确认

<https://gugulina.github.io/gpic-website/>

**如果还是旧内容，先按 `Ctrl + F5` 强制刷新。** GitHub Pages 有 CDN 缓存，
偶尔会多留几分钟，这属于正常现象，不用重跑脚本。

## 三、脚本会出现的三种结果

| 屏幕上看到 | 含义 | 要做什么 |
|---|---|---|
| `已推送完成` + 线上地址 | 正常，已上线 | 等 1～3 分钟，Ctrl + F5 看结果 |
| `库里内容与已在公网上的版本一致，没有需要推送的改动` | 你改的东西之前已经同步过了 | 什么都不用做，本来就没变 |
| `[X] ...` 失败提示 | 停在了某一步 | 见下面第四节 |

**关键一点：脚本报「没有需要推送的改动」时，不要去后台重复保存** ——
说明内容确实已经和线上一致了，再保存一次也只是把同样的值写第二遍。

## 四、出错怎么办

| 报错 | 原因 | 处理 |
|---|---|---|
| `找不到数据库 server\data\gpic.sqlite` | 还没启动过自持站 | 先双击「启动自持站.bat」跑一次 |
| `找不到 Python 3` | 系统里没有 Python | 装一个 Python 3，或改用自带环境 |
| `静态快照重建失败`，提示「断链」 | `web/` 里引用了不存在的图片 | 按报错里给出的路径补图，或改掉引用 |
| `git add 失败` | 文件被别的程序占用 | 关掉预览窗口 / 编辑器 / 同步盘，再重跑 |
| `git commit 失败`，提到 `user.email` | git 没配身份 | 命令行跑一次 `git config --global user.email "你的邮箱"` |
| `推送到 GitHub 失败` | 网络、代理、凭据 | 本地提交**不会丢**，修好网络后重跑脚本会自动补推 |
| 窗口里出现 `'上地址：' 不是内部或外部命令` | bat 里混进了中文，cmd 解析错位 | 已修复；如再出现见第六节 |

推送失败不必慌：`git commit` 已经完成，改动在本地仓库里躺着，
重跑脚本时它会检测到「有提交但没推送」，自动补推一次。

## 五、不双击 bat 时的手动做法

等价于脚本的三步，在项目根目录命令行执行：

```bat
cd 官网
node server\export.mjs                    :: ① 库 → content.json
python scripts\build-standalone.py        :: ② 重建静态快照
cd ..
git add -- "官网/data/content.json" "官网/web" "官网/web-standalone"
git commit -m "内容同步：后台改动上线"
git push origin main                      :: ③ 上线
```

只想在本地看效果、暂不上线，加 `--dry-run`：

```bat
同步到公网.bat --dry-run
```

它只做 ①②，把本地 `web-standalone/` 刷成最新，不提交、不推送。

## 六、两个必须守住的规矩

### 规矩一：`同步到公网.bat` 只能写英文

cmd 在 `chcp 65001`（UTF-8 代码页）下解析批处理时，多字节中文会让读缓冲
按字节/字符混算，**行首几个字符被吞掉**，表现为：

```
'上地址：' is not recognized as an internal or external command
'CDN' is not recognized as an internal or external command
```

实测三种组合：

| 组合 | 结果 |
|---|---|
| 中文 + `chcp 65001` | ❌ 吞字符 |
| 纯 ASCII + `chcp 65001` | ✅ 正常 |
| 中文 + 不开 `chcp`（默认 936） | ✅ 能跑，但窗口里中文乱码 |

所以现在的做法是：**bat 只留纯 ASCII 的启动逻辑，所有中文提示写在
`官网/scripts/sync-public.mjs` 里**（Node 输出 UTF-8 不受此影响）。
以后要改提示文案，改 `.mjs`，别往 `.bat` 里加中文。

### 规矩二：`.bat` 必须保持 CRLF 行尾

Windows cmd 按 CRLF 分块读批处理，LF-only 会让读缓冲错位、
同样表现为吞掉每行开头几个字符，典型报错：

```
'cho' is not recognized ...     (echo 少了个 e)
'his' is not recognized ...     (This 少了个 T)
```

仓库里已用 `.gitattributes` 锁定：

```gitattributes
*.bat   text eol=crlf
```

`.gitattributes` 保证的是**检出时**转换；如果你在别的编辑器里存成 LF，
提交后仍会被纠正回来，但本地那份要重新 checkout 才生效。

## 七、内容之外的常见坑

**商品图片要放对目录。** 前台读的是 `官网/web/assets/images/`，
根目录的 `官网/assets/images/` 只是源素材仓库，放那里前台看不到。
新图先放进 `web/assets/images/`，再跑同步脚本。

**别用 Qoder 改仓库。** 用 Qoder 打开这个项目并让它「提交/推送」，
会改动 GitHub 上的仓库状态，可能把本地这几次提交覆盖掉。
要改代码就在本地改、本地 commit、用本脚本推送。

**后台只在本机可用。** `admin.html` 不在公网站点上（公网是只读快照，
没有后端、没有数据库）。所以随时随地改内容这件事，目前只能在
跑着自持站的那台电脑上做。等以后上了云服务器才能远程改。
