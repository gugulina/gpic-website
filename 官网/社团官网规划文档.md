## 1. 项目背景与目标

### 1.1 现状

社团目前的内容发布与销售分散在多个平台（微博 / B站 / X / Pixiv / 闲鱼 / 微店 / QQ 群），缺少一个**属于自己、可长期沉淀、可对外统一引用**的官方入口。

### 1.2 官网要解决的三件事

1. **让不认识你的人 30 秒内看懂你是谁** —— 首屏必须出现社团名、一句话定位、主视觉。
2. **让已经喜欢你的人有集中的作品与购买入口** —— 画集画廊 + 通贩跳转一站式完成。
3. **给展会与媒体一个官方可信的落点** —— 摊位号、新品情报、联系方式集中发布。

### 1.3 非目标（明确不做，避免精力分散）

- ❌ 不做社区 / 论坛 / 留言板（维护成本高，收益低）。
- ❌ 不做站内支付与订单系统（触碰经营性网站红线，见第 6 章）。
- ❌ 不做会员体系、不做用户登录。
- ❌ 不做博客长文写作（公告保持短、频、准）。

### 1.4 成功指标

| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 首屏加载（LCP） | ≤ 2.5 秒 | Lighthouse / PageSpeed |
| 首屏资源体积 | ≤ 500 KB | 构建产物分析 |
| 单张画廊图体积 | ≤ 300 KB | 图片流水线校验 |
| 移动端可用性 | 无横向滚动、字号 ≥ 14px | 真机走查 |
| 作品页 → 通贩点击率 | ≥ 15% | 轻量统计工具 |

## 2. 内容定位

基于「画集插画 + 周边通贩」的主打方向，本站本质是一个 **视觉作品展示 + 电商导流** 型站点。

### 2.1 内容支柱

| 支柱 | 说明 | 对站点的要求 |
|---|---|---|
| 画集 / 插画 | 核心资产，访客停留时间的主要来源 | 高清但**必须极致压缩**，需灯箱浏览、原作信息、上下翻页 |
| 周边 / 通贩 | 变现与实际转化 | 商品卡 + 平台跳转 + 发售状态（预约 / 现货 / 售罄） |
| 情报 / 公告 | 新刊进度、参展信息 | 列表 + 详情，更新要轻量（Markdown 即可） |
| 社团人设 | 成员、理念、Logo、世界观 | 「关于」页 + 成员卡 |

### 2.2 由此得出的两条硬约束

1. **图片性能 = 网站生死线。** 画集站最常见的翻车是「首页 5 MB，手机打不开」。必须建立图片处理流水线（见 5.3）。
2. **站内只展示、不收款。** 通贩一律跳转闲鱼 / 微店 / Booth，规避备案与经营性质风险（见 6.2）。
3. **虚实分明。** 「幻想乡五大发电集团」等为东方 Project 二创架空设定，须在醒目位置声明，避免与现实中的企业与机构混淆（见 6.2 设定声明）。

- 每个商品卡：封面、名称、价格、状态徽章（预约中 / 现货 / 售罄）

## 4. 视觉与设计规范

### 4.1 视觉调性

**东方同人的灵性 + 电力工程的理性**，呼应社团名。避免过度繁复的装饰，整体走「干净的画册感」，把视觉重心让给作品本身。

- 关键词：符卡、星芒、电路、仪表盘、红白巫女配色
- 禁忌：大面积深色背景压住作品、霓虹发光、过多动效干扰看图

### 4.2 色彩体系

| 角色 | 色值 | 用途 |
|---|---|---|
| 主色 · 幻想红 | `#C8324B` | 主按钮、强调标题、当前导航态 |
| 辅色 · 魔法紫 | `#7C6BE0` | 次级按钮、标签、链接悬停 |
| 点缀 · 星辉金 | `#D9A521` | 徽章、倒计时、限定标识 |
| 文字主色 | `#1F2433` | 正文与标题 |
| 文字次色 | `#6B7288` | 说明、日期、辅助信息 |
| 分割/边框 | `#E4E7F0` | 卡片描边、表格线 |
| 页面底色 | `#F7F8FC` | 内容区背景 |
| 语义 · 成功 | `#3FAE6B` | 现货 / 已完成 |
| 语义 · 警告 | `#E8913A` | 预约中 / 临近截止 |
| 语义 · 错误 | `#E24B4A` | 售罄 / 错误提示 |

> 注意：本站为**内容展示类**，不使用股票涨跌配色约定。

### 4.3 字体与排版

| 场景 | 字体 | 字号 / 行高 |
|---|---|---|
| 中文标题 | 思源黑体 / Noto Sans SC | 24–40px / 1.3 |
| 中文正文 | 思源黑体 / Noto Sans SC | 15–16px / 1.7 |
| 日文 | Noto Sans JP | 同中文 |
| 西文与数字 | Inter | 同中文 |
| 代码 / 快捷键 | JetBrains Mono | 13px |

- 中文正文**不用衬线体**，保证移动端清晰度。
- 中日混排时，统一 `font-feature-settings` 并设置合理 `letter-spacing`（中文 0.02em）。
- 自托管字体子集化，避免加载完整字体包（一整套中文字体可达 5 MB+）。

### 4.4 核心组件规范

| 组件 | 规范 |
|---|---|
| 主按钮 | 高 44px、圆角 8px、主色填充、白字 |
| 次按钮 | 高 44px、描边式、主色文字 |
| 作品卡 | 图 3:4 或 4:3、圆角 12px、悬停轻微上浮 + 遮罩 |
| 状态徽章 | 高 22px、圆角 11px、语义色 20% 底 + 语义色文字 |
| 画廊灯箱 | 全屏遮罩 90% 黑、图片居中、左右箭头、ESC 关闭 |
| 公告条目 | 日期左置等宽、标签 + 标题、整行可点 |

### 4.5 响应式断点

| 断点 | 宽度 | 布局 |
|---|---|---|
| 手机 | < 640px | 单列、底部固定通贩入口 |
| 平板 | 640–1024px | 双列网格 |
| 桌面 | > 1024px | 三/四列网格，内容最大宽 1200px |

### 4.6 无障碍与暗色模式

- 图片必须写 `alt`；装饰性图片 `alt=""`。
- 正文与背景对比度 ≥ 4.5:1。
- 提供暗色模式（跟随系统偏好），画廊页在暗色下体验更好。

## 5. 技术方案

### 5.1 技术选型

**推荐：Astro（静态站点生成）+ Markdown 内容 + Git 托管 + 免费 CDN 部署。**

理由：

- 内容站首选，默认输出**零 JavaScript**，首屏极快，SEO 友好。
- 内容用 Markdown 写，改一条公告 = 改一个文件，无需数据库。
- 支持 Islands 架构，只有画廊灯箱等交互组件加载 JS。

备选：若团队更熟悉 React 生态，可用 **Vite + React + SSG 插件**。

### 5.2 建议目录结构

```
/
├── public/                    # 原始静态资源
│   ├── favicon.ico
│   ├── robots.txt
│   └── og/                    # 社交分享图
├── src/
│   ├── content/
│   │   ├── works/             # 作品（画集 / 插画 / 周边）.md
│   │   ├── news/              # 公告 .md
│   │   └── members/           # 成员 .md
│   ├── components/            # 卡片、灯箱、导航、页脚
│   ├── layouts/               # 页面骨架
│   ├── pages/                 # 路由
│   └── styles/                # 全局样式与设计变量
├── astro.config.mjs
└── package.json
```

### 5.3 图片处理流水线（本项目重点）

**流程：** 画师交稿（PNG/TIFF，大尺寸）→ 统一命名与归档 → 生成三档尺寸 → 转 WebP/AVIF → 上传对象存储 → 页面引用。

| 用途 | 尺寸 | 体积上限 | 格式 |
|---|---|---|---|
| 卡片缩略图 | 宽 400px | 60 KB | WebP |
| 详情预览图 | 宽 1200px | 200 KB | WebP |
| 灯箱原图 | 宽 2000px | 400 KB | AVIF / WebP |
| 原图下载 | 原始尺寸 | 不设限 | 仅在明确授权后开放 |

实施方式：构建时用 `sharp` 批量处理，或本地跑一次脚本生成到 `public/images/`；量大后迁移到对象存储 + CDN。

### 5.4 内容管理

| 阶段 | 方案 | 适用 |
|---|---|---|
| 起步 | Markdown + 编辑器 | 主催 1–2 人维护 |
| 扩展 | 接入无头 CMS（Decap CMS / Sanity），挂一个 `/admin` 后台 | 有非技术成员也要发公告 |

**画集条目的 Frontmatter 字段定义：**

```yaml
  - { name: 闲鱼, url: "https://..." }
  - { name: 微店, url: "https://..." }

```

### 5.5 部署与 DNS

见第 6 章「域名与合规」，两条路线对应两套部署。

### 5.6 性能预算（构建时校验）

- 首屏 CSS + JS ≤ 150 KB（gzip 后）
- 首屏图片总量 ≤ 350 KB
- 页面 HTML ≤ 60 KB
- 全站字体子集 ≤ 200 KB

### 5.7 实际实现说明（2026-09 现状，覆盖 5.1–5.5 的部分内容）

5.1–5.5 是**最初规划**（Astro + Markdown + Git 部署）。实际落地时为了让主催一人可维护、
且不依赖任何构建工具与国内不稳定的服务，改成了更轻的一条路：

| 项 | 规划 | 实际 |
|---|---|---|
| 页面 | Astro 组件化多页 | **单个 `index.html` 自包含**（CSS/JS 内联），内容驱动渲染 |
| 内容源 | Markdown + Frontmatter | **`data/content.json`**（单一 JSON 数据源） |
| 编辑方式 | 手写 Markdown / 无头 CMS | **本机 `admin.html` 后台**（`scripts/serve.py` 提供发布与上传接口） |
| 图片 | 构建期生成多规格 | `scripts/build-assets.py` 预生成 webp；后台上传时服务端自动转 WebP + 限宽 1600 |
| 部署 | Git 推送 + CI | `scripts/deploy.py` 打包 `dist/` → 手动上传到静态托管 |
| 版本与回滚 | Git 历史 | 服务端自动备份到 `data/.backup/`（保留 30 份）+ 后台一键回滚 |

**取舍理由**：无构建步骤 = 接手人不需要懂前端工具链；内容源是中立 JSON = 以后想迁到 CMS 只需"加一层"。
**代价**：后台只在本机可用，线上改内容必须走"本地发布 → 打包 → 上传"。

完整操作手册见 **`交接说明.md`**。

## 6. 域名与合规

### 6.1 域名建议

| 后缀 | 年费参考 | 说明 |
|---|---|---|
| `.com` | ¥60–80 | 首选，通用、可信度高 |
| `.cn` | ¥30–50 | 国内备案更顺，但需实名 |
| `.top` / `.icu` | ¥10–30 | 便宜，**务必看清续费价** |

命名建议：短、易拼、易口播。可考虑拼音缩写 + `studio` / `circle`，或直接用社团英文缩写。

### 6.2 备案路线（**因「国内同好为主」而成为关键决策**）

| 对比项 | 路线 A：海外托管 | 路线 B：国内托管 |
|---|---|---|
| 托管 | Cloudflare Pages / Vercel / Netlify | 阿里云 / 腾讯云轻量服务器 + OSS + CDN |
| 备案 | **免备案** | 需 ICP 备案（域名实名 + 审核，通常 7–20 个工作日） |
| 国内访问速度 | 一般，跨境网络波动时不稳定 | **快且稳定** |
| 成本 | 0 元/年 | 约 ¥10–50/月 |
| 上线速度 | 当天 | 2–4 周 |
| 适合阶段 | 起步、试水 | 长期、正式运营 |

**推荐策略：分两步走。**

1. **M1 阶段用路线 A 先上线**（免备案、零成本、当天可用），先把内容跑通、拿到可分享的链接。
2. **内容稳定后再切路线 B**：备好备案材料走 ICP，把图片与站点迁到国内 OSS + CDN。

**⚠️ 合规红线（必须遵守）：**

- 国内**个人备案**不得涉及经营性内容。站内**不得直接收取货款、不得出现购物车与在线下单**。
- 所有购买行为**跳转至闲鱼 / 微店 / Booth 等第三方平台**完成，站点仅做展示与导流。
- 静态页面不得出现违规内容；备案信息需与站点主体一致。
- 若未来确需站内交易，须变更主体为**企业/个体工商户**并办理 ICP 经营性许可。

**⚠️ 设定声明（同人站点特有）：**

- 站点通篇使用「幻想乡五大发电集团」等拟真企业设定，**必须在醒目位置声明其为东方 Project 二次创作架空设定**，避免与现实中的发电集团体系（含俗称的「五大」「六小」）产生混淆。
- 已落地做法：首页导航下方常驻「架空设定」声明条（`site.worldviewNote`）+ 品牌集群区备注 + 页脚非官方声明，三处呼应。
- 现实中的平台、展会、社交账号（闲鱼 / 微店 / Booth / QQ 群 / 微博等）属于**真实信息**，应与架空设定在版式上区分开（如平台链接放在「通贩商店」区、社群链接放在页脚社交矩阵）。

### 6.3 同人版权与二创声明

- 东方 Project 二次创作须遵守 **上海爱丽丝幻乐团（ZUN）的二次创作规约**：允许同人创作与贩售，但**不得损害原作形象、不得自称官方**。
- 每件作品页标注**画师 / 作曲 / Staff**；使用他人曲目或素材需取得授权并留档。
- 建议单独设立「二创声明 / 使用条款」页，声明：本站为非官方同人作品站、转载规范、商用联系邮箱。
- 开放原图下载需谨慎，默认关闭；仅在获得画师明确授权时开放。

### 6.4 隐私与统计

- 使用**轻量、隐私友好**的统计工具（Umami 自托管 / Cloudflare Web Analytics），避免 Cookie 弹窗。
- 若使用 GA 等带 Cookie 的工具，需增加 Cookie 同意提示。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 图片过大导致加载缓慢 | 访客流失，移动端直接打不开 | 强制图片流水线 + 构建期性能预算校验 |
| 国内访问不稳定 | 国内同好体验差 | 先海外托管验证，再走备案 + 国内 OSS/CDN |
| 备案与经营性内容冲突 | 无法通过备案或被关停 | 站内不收款，购买一律跳转第三方平台 |
| 版权或授权争议 | 下架、纠纷、口碑受损 | 遵守二创规约、署名完整、授权留档 |
| 人手不足导致断更 | 沦为「僵尸站」 | 固定责任人 + 模板化更新流程 |
| 素材或文案丢失 | 返工重做 | Git 版本管理 + 月度异地备份 |
| 域名到期未续费 | 站点下线、域名被抢注 | 开启自动续费 + 到期提醒 |
