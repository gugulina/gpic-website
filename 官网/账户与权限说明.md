# 账户与权限说明

> 一句话：**每个人可以自己改账户名（要验密码）；主催建号时勾「能改哪几页」，那个账号登录后侧栏就只剩那几页，
> 改别的页面一律 403。主催不受限制，永远全权。**

当前版本：v1.1.0（2026-10-19）

---

## 一、两种角色

| 角色 | 存的值 | 能做什么 |
|---|---|---|
| **主催** | `organizer` | 全部页面 + 数据迁移 + 账户管理。权限配置对它**完全无效** |
| **管理员** | `admin` | 只能改 `perms` 里勾上的那几个页面；没勾的页面前台侧栏看不见、接口调不动 |

改角色本身没有 UI（也没有接口）—— 目前只会由 `seed.mjs` 建出主催。这样设计是故意的：
社团里主催通常只有一个人，角色一旦能被界面改，就迟早出现「两个主催互相降权」。

---

## 二、权限的最小单位：后台一个页面

11 个内容域，和后台侧栏一一对应：

| 存的值 | 后台页面 | 管的是什么 |
|---|---|---|
| `settings` | 站点设置 | 站名、slogan、SEO、页脚文案、后台入口开关 |
| `hero` | 首页横幅 | 首屏大图、标题、按钮、数据条 |
| `notices` | 新闻公告 | 公告增删改、正文 blocks |
| `brands` | 品牌集群 | 五个成员品牌及 logo |
| `goods` | 周边商品 | 商品增删改、售罄/下架、首页精选、商品页底部两张卡 |
| `shop` | 通贩商店 | 通贩渠道链接 |
| `event` | 参展活动 | 参展信息、摊位、日期 |
| `recruit` | 人员招募 | 招募岗位与说明 |
| `social` | 社交链接 | QQ 群、闲鱼等 |
| `about` | 关于我们 | 社团介绍、身份标签、业务标签 |
| `images` | 图片管理 | 上传 / 删除图片 |

**不在这个清单里的两页**：「数据迁移」会覆盖全站内容，「账户管理」能改别人的账号与权限 —— 都只给主催。

### 为什么是「页面」而不是「字段」

按字段授权听起来更细，但实际运维里没人会记得「张三能改公告标题不能改公告正文」。
按页面分，社团里说什么话都清楚：**「你负责公告和商品」**，就勾两个。

## 三、改自己的账户名

位置：后台侧栏 → **我的账户** → 账户名。

规则：

| 规则 | 说明 |
|---|---|
| 2–32 位，只能英文、数字、下划线 | 和建号时的规则一致 |
| 必须输入**当前密码** | 后台常在公用电脑上开着不登出。只凭登录态就能改名的话，别人可以先把名字改成他的，再用自己的密码登进来 |
| 不能和别人重名 | 数据库里 `username` 是 UNIQUE |
| **改完不用重新登录** | 会话认的是 `user_id`，不是用户名 |
| 改完旧名字立刻失效 | 下次登录要用新名字 |

主催也可以改自己的名字，走同一个入口；主催也可以在「账户管理 → 编辑」里改自己的名字。

## 四、给新账号配权限

位置：后台侧栏 → **账户管理**（只有主催看得见）。

### 建号时直接配

1. 点「+ 创建管理员」
2. 填用户名、初始密码
3. 在「可编辑页面」里勾上他负责的页
4. 点「创建」

那个账号第一次登录，侧栏就只剩勾上的那几页 —— 不是登进去再藏起来，是压根没有入口。

### 之后调整

在账户列表里每一行点「编辑」，改勾选后保存。**保存即生效**，对方不用重新登录：
每次请求都会重新读一遍权限（`requireAuth` 每次查 `users.perms`），所以收权是立刻的，不用等他刷新。

列表里每行都显示权限摘要（「新闻公告、周边商品」/「全部页面」/「无编辑权」），不用点开才知道。

### 不勾任何页面会怎样

能登录，能看仪表盘，能改自己的名字和密码，其他什么都做不了。适合「先建号，等确定了再配权力」。

## 五、后端怎么拦

### 一处登记，全部生效

`functions/handler.mjs` 里有一张 `ACTION_PERM` 表，把每个写接口映射到内容域：

```js
const ACTION_PERM = {
  save_notice: "notices",
  delete_notice: "notices",
  save_good: "goods",
  set_good_status: "goods",
  save_home_goods: "goods",
  ...
  change_password: null,        // 登录即可
  rename_self: null,
  update_user: "__organizer__", // 主催专属
};
```

> ⚠️ **新增写接口必须来这张表登记。** 没登记的写接口会被默认拒绝（403 `action_not_permitted`），
> 不是默默放行 —— 这是 fail-closed，宁可当场报错，也不能让接口裸奔。

### 三道关卡

1. **没登录** → 401 `login_required`
2. **登录了但没这个域** → 403 `forbidden` + `domain: "goods"`（前端能直接说清缺哪页）
3. **主催专属接口被普通管理员调用** → 403 `forbidden`

### GET 也管

`admin_goods`（含下架商品的完整列表）走 GET，但要求 `goods` 权限 —— 否则没授权的人也能把下架商品全拉下来。
其余 GET 都是公开内容（首页、公告、商品），不设权限。

### 前端隐藏只是体验

侧栏隐藏、面板不显示，都是让人别点进死路。真正的边界在后端。
**手动改 DOM 把按钮弄出来，保存照样 403。**

## 六、数据怎么存

`users` 表新增一列：

```sql
perms TEXT   -- {"notices":"write","goods":"write"}
```

- `NULL` 或 `{}` = 没有任何编辑权
- 存**对象**而不是数组：以后想加「只读」档，把 `write` 换成 `read` 即可，不用改表、不用迁移数据
- `organizer` 忽略这一列（永远全权），但仍然会写入全部域 —— 将来把它降成管理员时不用重配一遍

### 老库升级

```bash
node server/migrate-users-perms.mjs --dry-run   # 先看要改什么
node server/migrate-users-perms.mjs             # 加列 + 回填
```

回填策略：**所有权限为空的账号都给「全部内容域可写」**。因为改造前所有管理员本来就能改全部页面，
不回填的话升级当晚所有人都会突然写不了东西。想收权，升级完一个个改。

脚本幂等，反复跑安全。

## 七、常见场景

### 「新来一个管公告的」

账户管理 → 创建管理员 → 勾「新闻公告」→ 创建。完事。

### 「商品这边给运营，但他不能动首页横幅」

勾「周边商品」，别勾「首页横幅」。首页横幅管的是首屏大图，和商品页的图完全是两回事。

### 「实习生只能看图，不能改」

现在的授权只有「能改」一档，没有只读。折中办法：不勾任何页 —— 他连图库都进不去。
真需要只读，得在 `perms` 里加 `read` 档（数据结构已经预留，见第六节）。

### 「有人离职了」

账户管理 → 找到他 → 删除。删除会同时清掉他的所有会话（`auth_sessions`），立刻失效。

### 「我不小心把自己降权了」

不会发生：主催的权限配置无效，主催也不能改别的主催。

## 八、排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 侧栏少了几项 | 正常，没勾那些页 | 主催去账户管理里加 |
| 点保存提示 403 `forbidden` | 这个页没授权 | 同上 |
| 403 里带 `domain: "xxx"` | 就是缺这一页 | 同上 |
| 改完名登录不进去 | 用的是旧名字 | 用新名字登 |
| 改名提示「当前密码错误」 | 输的是新密码或记错了 | 重新输当前密码 |
| 升级后所有人都写不了 | 漏跑迁移脚本 | 跑 `migrate-users-perms.mjs` |
| 新加了个接口，一调就 403 `action_not_permitted` | 忘了在 `ACTION_PERM` 里登记 | 去登记 |

## 九、接口清单

| 接口 | 方法 | 谁能调 | 说明 |
|---|---|---|---|
| `login` | POST | 公开 | 返回 `user.perms`，前端据此摆侧栏 |
| `rename_self` | POST | 登录即可 | `{username, password}`，返回新用户名 |
| `change_password` | POST | 登录即可 | 改自己的密码 |
| `list_users` | POST | 主催 | 返回 `items`（含 `perms`）与 `domains` |
| `create_user` | POST | 主催 | 支持 `perms`，非白名单域会被丢弃 |
| `update_user` | POST | 主催 | `{id, username?, perms?}`，不能改别的主催 |
| `delete_user` | POST | 主催 | 不能删自己，不能删主催，顺带清会话 |
