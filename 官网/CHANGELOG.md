# 版本记录

幻电投企划官网的对外版本号。规则见 [版本号规范.md](版本号规范.md)。

- 版本号格式：`MAJOR.MINOR.PATCH`
- 真源：`web/version.json`（改版本只走 `node scripts/version.mjs bump ...`）
- **不要和 `content.json` 的 `version: 5` 搞混** —— 那是内容结构版本，管的是"前端能不能读懂这份数据"，跟对外版本号是两条线。

## [1.2.0] · 2026-10-19 · 异地交接与登录限流

这一版解决的是「把后台交给不在同一台电脑上的人」这件事。

- **登录失败限流**：同一「用户名 + 来源 IP」15 分钟内错 5 次锁 15 分钟，
  返回 429 且带 `retry_after`。暴露到虚拟局域网之前这是必需品，
  否则对方账号一旦泄露就是无限次试密码
- **来源 IP 由服务端写入**：客户端自带 `x-gpic-client-ip` 一律丢弃，
  换个请求头绕不过限流
- **`启动自持站（远程）.bat`**：监听 `0.0.0.0`，启动时把真实网卡地址打印出来
  （含 `100.x` 虚拟局域网段标注），避免有人把 `127.0.0.1` 发给对方
- **登录页提示中文化**：被限流时直接说「失败次数太多，请 N 分钟后再试」，
  不再把 `too_many_attempts` 原样糊在脸上
- **《后台上手与交接说明.md》**：建号勾权限、Tailscale 连法、防火墙、
  「保存 ≠ 上线」、安全红线、交接清单、排错表
- e2e 新增 7 条限流断言，总数 180

## [1.1.0] · 2026-10-19 · 账户改名与分页面授权

把「所有管理员权限一样」拆成「一个人只管他负责的那几页」。

- **账户改名**：每个人都能改自己的账户名，需验证当前密码。会话认 `user_id` 不认用户名，改完不用重新登录
- **分页面授权**：主催建号时勾选「能改哪几页」（11 个内容域），侧栏与接口同时受限；没勾的页面压根没有入口
- **后端鉴权重构**：`ACTION_PERM` 一处登记，写接口漏登记默认 403（fail-closed）；403 带 `domain` 字段说明缺哪页
- **GET 也管**：`admin_goods`（含下架商品）要求 `goods` 权限，否则没授权也能把下架商品拉下来
- **主催专属两项**：数据迁移、账户管理。主催不可被改角色、不可被删，避免唯一主催把自己锁死
- **修一个老 bug**：改密码表单原来放在「账户管理」页里，而那一页只有主催看得见 —— 普通管理员实际上改不了自己的密码。现在挪到独立的「我的账户」页，所有账号可进
- **数据**：`users` 新增 `perms` 列（JSON 对象）；`server/migrate-users-perms.mjs` 把老账号回填为全权，升级前后能改的页面不变
- **回归**：e2e 新增 23 条权限断言，总数 173 项；后台界面 18 项

内容结构版本：`contentVersion 5`（未变）。


## [1.0.0] · 2026-10-19 · 自持站正式版

第一个可以完整交付的版本：内容不再依赖任何第三方平台，改完内容点一个脚本就能上公网。

- **自持动态站**：Node 22 + `node:sqlite`，零 npm 依赖，一条命令起站。替代原 Qoder Sites + Supabase（额度用尽后整站 429）
- **后台可控内容**：站点设置、首页横幅、公告（含 blocks 自由排版）、品牌、商品、通贩、参展、招募、社交链接、图片上传（自动转 WebP）
- **商品三态**：`on_sale` / `sold_out` / `off_shelf`，后台可手动切换；售罄仍展示但沉底，下架前台完全不可见
- **首页商品精选**：有序 id 数组，后台可加入/移除/排序，未入选商品不出现在首页
- **两条发布通道**：自持站直出；`同步到公网.bat` 导出 content.json → 构建静态快照 → 推 GitHub Pages
- **备份体系**：`备份.bat` 一键全量快照 + bundle，含 git 探测兜底
- **版本号机制**：`web/version.json` 单一真源，页脚 / 响应头 / 提交信息 / git tag 全部由脚本派生（本版新增）

内容结构版本：`contentVersion 5`（未变）。
